# 分家 YSD9000 版 MK09 の記録

MK09 は MC6809 用のこの木が**本家**である。別の CPU (YSD9000、独自の 32 ビット RISC 風 CPU。Tang Nano 9K 上に実装) への移植が分家として
`YSD9000_poc` (https://github.com/kaya-z/YSD9000、`mk09/` と `docs/MK09.md`) にあり、そこでは本家にない機能が先に作られている。
このファイルは、**分家にあって本家にない機能**を記録として残す。本家へ取り込んだものは [DESIGN.md](DESIGN.md) 章 16 の改版履歴を見る。
この記録は 2026-10-27 の時点 (分家 MK09 1.13、本家 1.6 を取り込んだ後に分家が 1.14) のものである。

## 1. 本家との対応 (版)

| 分家の版 | 内容 | 本家 |
|---|---|---|
| 1.1 〜 1.3 | 複数プログラム同時実行、MM を独立タスクに、`stk` | 本家 1.1 〜 1.3 に対応 (本家が先、または同時) |
| 1.4 | BASIC 1.1 (内部形式、式のコンパイル)、タイマ割り込みの高速経路 | BASIC は 1.3 で取り込み済み。高速経路は取り込まない (4 節) |
| 1.5 | MK09 の上の as / ld / ar、引数 16 個、「stopped by the system」 | 引数と「stopped」だけ 1.6 で取り込み |
| 1.6 〜 1.8 | MK09 の上の C コンパイラ (cpp, cc1, inl, cg)、最適化 | 取り込まない (3 節) |
| 1.9 | MK09 の上の Pascal | 取り込まない (3 節) |
| 1.10, 1.11 | シェルのパイプ、`more` の標準入力 | 本家 1.6 で取り込み |
| 1.12, 1.13 | コンパイルの高速化 (`fseek`、`ld` の索引、FS キャッシュ 8 ブロック、DISK の 8 バイト転送) | 取り込まない (4 節) |
| 1.14 | 本家 1.4 / 1.5 の IPC 高速化を分家のカーネルへ | 逆向きの取り込み (本家 → 分家) |

## 2. 本家の MK09 と違う CPU 構成

分家は同じサーバ構成 (TTY / DISK / FS / PM / MM) とメッセージ体系をそのまま使い、CPU に依存する部分だけを作り直している。

* **メモリ**: タスクごとに別のアドレス空間 (UMAP、4 KB × 16 ページ)。他のタスクのメモリは見えない。本家の「領域 (lo..hi) の検査」の代わりにページフォルトで
  そのタスクだけを終了する。論理 0x1000 から全員が始まるので、再配置できるプログラム (MX v2) は要らない。
* **システムコール**: `TRAP #0`、レジスタ渡し (r0..r4)。C のスタブは `tools/gensys.py` が作る。カーネルは C 版だけ (`kernel/kernel.c` と `arch/ysd9000/`)。
* **コンソール受信は割り込み駆動**: IRQ1 のハンドラがカーネルの 256 バイトのリングへ文字を移し、TTY に `NFY_RX` で知らせる (`SYS_RXGET`)。
  本家は TTY が毎ティック ACIA を読む。分家では 9600 baud の貼り付けが欠けなくなった。
* **ディスク**: YSD8003 (読み出し専用) では書いたブロックを RAM のオーバレイ (最大 256 KB、`SYS_XBLK`) に持つ。再起動で消える。YSD8003A なら SD に書く。
* **`reboot`** (PM の `PM_REBOOT`、カーネルの `SYS_REBOOT`)、`shutdown` で `system halted` の表示 (`bsp_power_off`)。
* **カーネルの時間**: 本家 1.4 / 1.5 の高速化 (1 回の `pick()`、`sendhint`、窓 1 回のメッセージ複写) を 1.14 で取り込み、往復 3900 → 3240 μs。
* 別系の OS (SORA、FUZIX) とは SD の起動ブロックで切り替える。MK09 のイメージは `mk09/build/mk09.img`。

## 3. MK09 の上の開発環境 (本家に無い。YSD9000 の機械語を作るので取り込めない)

MK09 の中でプログラムを作れる。どれも CPU 依存 (YSD9000 のアセンブリ・オブジェクト) なので、6809 には移せない。6809 の CMOC / LWTOOLS を MK09 の上に載せる案は
メモリ (1 プログラム 60 KB 以内) と無関係に大きすぎるので考えていない。

| 段階 | 版 | 内容 |
|---|---|---|
| 1 | 1.5 | `as` `ld` `ar`。クロス版と同じ言語・出力 (YOF1 オブジェクト、YAR1 アーカイブ、リンカスクリプト、hex / yxe / bin / map)。ファイルをメモリに載せない作り (as: シンボル表だけ、約 500 ラベル/ファイル。ld: 一時ファイルで再配置、`-f mx` で MK09 の実行ファイル)。`/LIB` `/DEV` |
| 2 | 1.6 〜 1.8 | C コンパイラ。`cpp` → `cc1` (宣言・型・式の木) → `inl` (小さい関数の展開) → `cg` → `as` → `ld`。各段はファイルでつなぐ (60 KB の制約)。ドライバ `cc`。レジスタ変数、ループの反転、インライン asm、`interrupt` 属性。Dhrystone は `ysd-cc -O2` の約 82% |
| 3 | 1.9 | Pascal。`pas1` が C の `cc1` と同じ中間言語 (`cdef.h`) を書き、あとは C と共通。Pascal-S に近い部分集合 (入れ子の手続き、record、ポインタ、case、longint。real / set / string / file は無い)。`cc` が `.pas` を受け取る。`docs/PASCAL.md` |

* 検査: `mk09/tests/dev_host_test.py` (PC 上の同じソースを、リポジトリのアセンブリと C の出力で比較)、`mk09_test.py` (MK09 上で `cc` が `hi.c` / `hip.pas` をコンパイルして実行)。
* 1.12 / 1.13 はコンパイル時間の短縮 (`hip.pas` 77 秒 → 41 秒、`hi.c` 82 秒 → 51 秒、シミュレータ)。内容は 4 節。

## 4. 本家に取り込まなかった改良とその理由

| 項目 (分家の版) | 内容 | 理由 |
|---|---|---|
| タイマ割り込みの高速経路 (1.4) | カーネルに入らずにその場で tick を数える (条件: ユーザタスク実行中、誰も眠っていない、SP が領域内、スライス継続) | 本家は TTY が毎ティック ACIA をポーリングするのでカーネルへ入る必要がある。低位メモリのコード枠にも空きがない (本家カーネルのコード余裕は数バイト) |
| `sleep_any` / HOOKDIV (1.4) | 眠っているタスクが全員 sleep のときの判定の短縮 | 同上。本家の idle / pick は 1.4 で別の形に高速化済み |
| FS の 8 ブロックキャッシュ (1.13) | FAT・ディレクトリ・データが 2 ブロックのキャッシュを奪い合うのを解消 | 本家の高位メモリ ($E200-$FEFF) はほぼ満杯 (キャッシュ 1 ブロック = 512 バイト増えるごとに別の何かが入らなくなる)。ボトルネックも FS ではなく IPC とディスクだった |
| DISK のセクタ転送を 8 バイトずつ (1.13) | ループの展開 | 6809 は DISK のデータが $0110 へ移っていて余白が無く、効果も小さい |
| `fseek` の先読みバッファ内処理、ld の索引など (1.12) | 開発ツールの高速化 | 開発ツール自体が本家にない |
| `reboot` (0.6) | PM + カーネルでシステムリセット | 本家にはシステムリセットを起こす装置の取り決めがまだない (分家は YSD8F00 の RESET)。必要になれば別に設計する |
| カーネルスタックの余裕検査 (1.11) | カーネルが仕事をする前にスタックが 400 バイトあるか検査 | 分家のカーネル構造に結びついた検査 (本家はシステムコールごとに `chkstack` でタスクの領域を検査している) |
| YMK (後の SORA) の `#ifdef` | OS 名の違いによる条件分岐 | 本家は MK09 だけ |

## 5. 逆に、本家が持ち、分家が持たないもの

* 再配置できるプログラム (MX v2) とメモリマネージャのページ (256 バイト) による「同時に複数のプログラム」(本家 1.1)。分家は別アドレス空間なのでページ割当てが粗い (4 KB)。
* 6809 のアセンブラ版カーネル (`arch/m6809/kernel.s`) と、そのクラス別の `pick` (本家 1.4)。分家は C 版のカーネルだけ。
* SD ブートローダ、Tang Nano 9K の 6809 核 (別の RTL) 上の実機動作と LED による起動報告。
* jwp の EUC / Shift_JIS 版 (本家の jwp のもの)。分家は SKK 辞書 (`/SKK/SKK.DIC`) の版を持つ。
* `grep`、`life`、`dhry`、`mandel.bas` などのアプリは両方にある。`sfp` の足し算・掛け算・割り算は本家が 6809 アセンブラ (`sfpa.s`)、分家は YSD9000 アセンブラの `sfpa.s`。
