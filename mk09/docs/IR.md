# MK09 の中間表現 (IR) と C コンパイラ

**版: 0.1** (2026-10-27。MK09 1.8 で作り始めた)

MK09 の上で C のプログラムを作る (開発環境の第 2 段階。第 1 段階はアセンブラ `as`、[DESIGN.md](DESIGN.md) 17 章)。
C コンパイラは**中間表現 (IR) を経由する 2 つのプログラム**で、アセンブラ文を直接は作らない。

```
 foo.c ──► cc1 ──► foo.ir ──► cg ──► foo.s ──► as ──► foo.mx
          (前処理、構文、型、IR を出す)   (IR から 6809 のコード)
```

* `cc1`: C の部分集合を読んで IR を出す。6809 のことは知らない (`int` が 16 ビットで、バイトが 8 ビットとだけ決めてある)。
* `cg`: IR を読んで 6809 のアセンブラ文を出す。C のことは知らない。
* ドライバ `cc`: 上の 3 つを順に走らせ (間はファイル)、ライブラリの関数を探して足す。
* 段の間をファイルにするのは、1 つのプログラムが TPA の約 41KB しか使えないため。IR は**テキスト**で、1 行に 1 命令なので、人が読めて、PC でも試験できる
  (`tools/irsim.py` は IR を直接実行する。`cg` と無関係に `cc1` の正しさを調べられる)。

## 1. 考え方

* **スタックマシン**。値は全部 **16 ビット** (`int`、ポインタ、`char` を読んだ値、真偽値)。式は後置の形で出る。木も一時変数も使わないので、`cc1` が小さくできて、
  `cg` は「スタックの一番上は D レジスタ」という約束でよいコードにできる (`const 5; add` → `addd #5` のように、定数や変数を直接使う)。
* 型の情報は IR に残さない。大きさと符号は、命令の種類 (`load.b` `load.ub` `load.w`、`lt` `ult`) に入っている。ポインタの足し算の倍率は `cc1` が掛け算にして出す。
* **ラベルとジャンプの所で、スタックの深さは決まっている** (`?:` と `&&` `||` は、結果を 1 つ積んで合流する)。`cg` は、ラベルとジャンプの所で、全部をスタックに実体化する。
* 名前は C の名前そのまま (`cg` が `_` を付ける)。`cc1` が作る名前は、ラベル `L数`、文字列 `S数`、関数の中の `static` 変数 `V数` で、C の名前とぶつからない。

## 2. ファイルの形

テキスト。行頭の `;` から行末まではコメント。空行は無視。空白で区切る。

### 2.1 宣言

| 行 | 意味 |
|---|---|
| `.extern NAME` | NAME は別の場所で定義されている (ライブラリの関数や変数)。ドライバがこれを見て、ライブラリから足す |
| `.data NAME [local]` | 初期値のあるデータの始まり。次の行から `.end` までがデータ行。`local` はこのファイルの中だけ (`static`) |
| `.bss NAME SIZE [local]` | 初期値のない SIZE バイト (起動時に 0) |
| `.func NAME FRAME [local]` | 関数の始まり。FRAME は局所変数の領域のバイト数。次の行から `.end` まで |
| `.end` | `.data` `.func` の終わり |

データ行 (`.data` の中): `.b n,n,...` (バイト)、`.w n,n,...` (ワード)、`.wa NAME[+n]` (NAME のアドレスのワード)、`.s "文字列"` (その文字のバイト。NUL は付かない。
`\n` `\t` `\\` `\"` `\xHH` が使える)、`.z n` (n バイトの 0)。

### 2.2 関数の中

* 引数は 16 ビットずつ。**右の引数から先に積む** (最初の引数が最後に積まれる。可変個の引数のため)。`paddr i` が i 番目 (0 から) の引数のアドレス。
* 局所変数は、関数の領域 (FRAME バイト) の中。`laddr off` が先頭から off バイト目のアドレス。
* ラベルは `名前:` の 1 行。

## 3. 命令

スタックの効果を ( 前 -- 後 ) で書く (右が上)。`a` はアドレス、`v` は値。

| 命令 | 効果 | 意味 |
|---|---|---|
| `const n` | ( -- n ) | 定数 (−32768..65535) |
| `addr NAME[+n]` | ( -- a ) | グローバルのアドレス、関数のアドレス、文字列のアドレス (+n は n バイト先) |
| `laddr off` | ( -- a ) | 局所変数の領域の off バイト目のアドレス |
| `paddr i` | ( -- a ) | i 番目の引数のアドレス |
| `load.b` `load.ub` `load.w` | ( a -- v ) | 符号つきバイト、符号なしバイト、ワードを読む |
| `store.b` `store.w` | ( a v -- v ) | v を a に書く (バイトは下位 8 ビット)。**v を残す** (代入式の値) |
| `postinc n` | ( a -- v ) | ワード a の値を v として残し、a のワードに n を足す (`p++` の値が要るとき。n は負でもよい) |
| `dup` `drop` `swap` | | 複製、捨てる、入れ替え。`over` ( a b -- a b a ) もある |
| `add` `sub` `mul` | ( a b -- a op b ) | 足す、引く、かける (16 ビット) |
| `div` `mod` `udiv` `umod` | ( a b -- a op b ) | 符号つき、符号なしの割り算とあまり (0 で割ると結果は 0) |
| `and` `or` `xor` | ( a b -- a op b ) | ビット演算 |
| `shl` `shr` `ushr` | ( a b -- a op b ) | 左シフト、算術右シフト、論理右シフト (b は 0..15) |
| `eq` `ne` `lt` `le` `gt` `ge` | ( a b -- 0/1 ) | 符号つきの比較 |
| `ult` `ule` `ugt` `uge` | ( a b -- 0/1 ) | 符号なしの比較 (`eq` `ne` は共通) |
| `neg` `com` `not` | ( a -- v ) | 符号反転、ビット反転、論理否定 (0 なら 1、そうでなければ 0) |
| `sx` `zx` | ( v -- v ) | 下位バイトを符号拡張、ゼロ拡張 (`char` へのキャスト) |
| `jmp L` | | 無条件ジャンプ |
| `jz L` `jnz L` | ( v -- ) | v が 0 のとき、0 でないとき、ジャンプ (v は捨てる) |
| `call NAME n` | ( args -- r ) | 関数を呼ぶ。n 個の引数を呼ぶ側が積んでいる。呼ぶ側が捨て、結果を 1 つ積む (`void` 関数は 0 を積む) |
| `calli n` | ( a args -- r ) | 関数ポインタ a を呼ぶ。a は n 個の引数の**下**にある (呼ぶ側が最初に積む)。a も呼ぶ側が捨てる |
| `ret` | ( v -- ) | 関数から値 v で戻る |
| `copy n` | ( d s -- d ) | n バイトを s から d へ写す (構造体の代入。領域は重ならない) |

関数の終わり (`.end`) に来ると 0 で戻る。

## 4. 例

```c
int sum(int n) { int i, s = 0; for (i = 1; i <= n; i++) s += i; return s; }
```
```
.func sum 4
    const 0
    laddr 2          ; s
    ... (store, drop)
```
(実際の出力は試験の `tests/cc/*.ir` を見る。)

## 5. コード生成 (`cg`)

`cg [-p接頭辞] [-o out.s] file.ir` は IR から `as` が読むアセンブラ文を作る。

* **呼び出しの約束**: 呼ぶ側が引数を右から積み (最初の引数が S の一番上)、`JSR` で呼び、`LEAS` で自分で捨てる。結果は D。U は枠のポインタで、呼ばれた側が保つ
  (`pshs u / leau ,s / leas -N,s` ... `leas ,u / puls u,pc`)。X Y D は自由に壊してよい。引数は `4,u` `6,u` ...、局所変数は `-N,u` から。
  (CMOC の約束と同じなので、`lib/mksys.s` の形のシステムコールの断片がそのまま使える。)
* **名前**: C の名前の前に `_` (関数 `foo` は `_foo`)。コードのラベルは関数の中の局所ラベル `@L<n>`、文字列と static 変数は `S<n>` `V<n>` で、
  `-p` で渡した接頭辞が前につく (複数のファイルをつなぐときにぶつからないように、ファイルごとに別の接頭辞を使う)。
* **IR のスタックの模擬**: `cg` は IR のスタックを、要素の記述 (定数、アドレス、D の中の値、まだ読んでいないメモリのワード、ハードウェアスタックのワード) の並びとして
  持つ。命令はそれを直接使う (`addd 4,u` `cmpd #5` `std -2,u`)。不変条件: ハードウェアスタックに積んだ要素は下の方にまとまり、D を使う要素は 1 つまで。
  ラベルとジャンプでは全部をハードウェアスタックに積む。
* **比較とジャンプ**: 比較の次の行が `jz` `jnz` なら 1 つにまとめて (`cmpd` + `jbxx`)。そうでなければ 0/1 を作る。分岐は `as` の `jbxx` (近ければ短い分岐) で出す。
  比較と分岐の間に `ldx` `pshs` などを入れてはいけない (フラグが変わる): スタックに残った要素は比較の前に積む。
* **ラベルの別名**: `alias A B` は第 1 パスで集めて、A へのジャンプを B へのジャンプにする (アセンブラの `equ` は使わない。後ろで定義される名前の値は第 2 パスの前半では古いため)。
* **ライブラリ**: `lib/cc/rt.s` (掛け算・割り算・シフトの断片 `__mul` `__div` `__mod` `__udiv` `__umod` `__shl` `__shr` `__ushr` `__copy`、システムコール)、
  `lib/cc/clib.c` (C で書いたライブラリ: `printf` `putchar` `puts` `open` `read` `write` ...)。どちらも `;@def 名前` で区切った断片で、`cg` は使う断片を
  `;@ext 名前` の行で知らせる (ドライバ `cc` はこれを見て必要な断片だけを足す)。

## 6. C の部分集合 (`cc1`)

`char` `int` `unsigned` `signed` `short` (int と同じ) `void`、ポインタ、配列、`struct` `union` `enum` `typedef`、関数ポインタ、`static` `extern` `const` (読み飛ばす)、
`sizeof`、キャスト、`?:` `&&` `||` `,`、代入と複合代入、`++` `--`、`if` `while` `do` `for` `switch` `break` `continue` `goto` `return`、初期化子 (配列、構造体、文字列)、文字列の連結、
前処理 (`#include` `#define` (名前だけと関数形式) `#undef` `#if` `#ifdef` `#ifndef` `#else` `#elif` `#endif`)。

**ない**もの: `long` `float` `double`、ビットフィールド、K&R 形式の関数定義、構造体を値で渡す・返すこと (代入はできる)、`#` と `##`、可変個の引数を持つマクロ。
名前は 14 文字までが有効。
