# SPI LCD (ILI9341 / MSP2807) 文字画面: 検討とシミュレーション

Tang Nano 9K に、ILI9341 の SPI モジュール (**MSP2807**、秋月電子、2.8 インチ、320×240、タッチ付き) をつないで、HDMI 文字画面と同じ文字画面を出す検討です (2026-11-05)。
40 ピンの RGB-LCD 版は [LCD.md](LCD.md) にあります。

**状態: RTL を書いて、シミュレーション (Verilator、ILI9341 の動作モデル付き) と Gowin のビルド (資源とタイミング) で確かめました。実機には書いていません。**
既存の RTL (`fpga/tn9k/rtl/`、`lcd/`) と制約ファイルは、1 つも変えていません。追加したものは `fpga/tn9k/spilcd/` にあります。

## 1. 構成

| ファイル | 内容 |
|---|---|

| `spilcd/rtl/spilcd_paint.v` | ペインタ。起動の列、変わったセルの検出、1 セルの描画 |
| `spilcd/rtl/spilcd_spi.v` | SPI のマスタ (モード 0、D/CX 付きの 8 ビット。1 バイト分の待機レジスタがあり、バイトが隙間なく続く) |
| `spilcd/rtl/tn9k_spilcd_top.v` | トップ (`tn9k_top.v` の HDMI の所を SPI 画面に替えたもの)。PLL は `lcd/rtl/lcd_pll.v` (33.75MHz の画素クロック) を使う |
| `spilcd/constraints/spilcd.cst`、`spilcd.sdc` | SPI のピンとクロックの制約 (ピンは仮。7 章) |

| `spilcd/scripts/build_spilcd.sh` | Gowin のビルド (資源とタイミング) |

## 2. 仕様の根拠

**ILI9341** (データシート V108 のテキストを抽出して確認):
* 4 線 SPI (IM[3:0] = 0110 または 1110)。**書き込みのクロック周期は 100ns 以上 (10MHz まで)、H と L の幅は 40ns 以上**。データの設定時間と保持時間は 30ns、CS から最初の SCL まで 40ns、D/CX の設定時間は 10ns。
* ロジック電圧 (VDDI) は 1.65〜3.3V。
* ソフトリセット (`01h`) のあと 5ms、スリープ解除 (`11h`) のあと 5ms (表示は 120ms) 待つ。
* `3Ah` の DBI[2:0] = 101 で 16 ビット/画素 (`0x55`)。電源投入時の既定は 18 ビット (110)。1 画素は 2 バイト、上位バイトから。
* `2Ah` (列)、`2Bh` (ページ)、`2Ch` (書き込み開始)。`36h` (MADCTL: MY MX MV ML BGR MH)。`33h` / `37h` でハードウェアの縦スクロール。

**MSP2807** (秋月の資料):
* ILI9341、320×240、4 線 SPI、65K 色。VCC は 3.3〜5V、**ロジックは 3.3V (TTL)**。
* 14 ピン: 1 VCC、2 GND、3 CS、4 RESET、5 DC/RS、6 SDI (MOSI)、7 SCK、8 LED (バックライト。H で点灯。制御しないなら 3.3V に常時接続)、9 SDO (MISO)、10〜14 タッチ (T_CLK T_CS T_DIN T_DO T_IRQ)。SD スロット付き。
* 消費電流は資料に「TBD」。初期化の列、バックライトの電流、レギュレータのジャンパは、資料にない。

## 3. 設計

**向きは横向き (40 桁 × 15 行)** です (ユーザーの決定)。フォントは既存の 8×16 と 16×16 の漢字 (1 行に 20 字)。縦向きなら、ハードウェアスクロールが使えますが、
横向きでは使えません (スクロールは GRAM の縦方向だけ)。

**ペインタ**: ILI9341 はフレームメモリを持つので、画面のリフレッシュは要りません。ターミナルが書くビデオ RAM (40×15 セル) を、ペインタが次のように写します。
1. セルを順に見て、ビデオ RAM の語 (と、カーソルの反転の有無) を、「前に描いた語」のコピー (シャドウ RAM) と比べる。
2. 違うセルだけを送る: `2Ah` (列 8 画素)、`2Bh` (行 16 画素)、`2Ch`、128 画素 (RGB565 で 256 バイト)。1 セル = 267 バイト。
3. 描いた語を、シャドウ RAM に書く。

変わった所だけが送られるので、キー入力や編集では一瞬で済みます。何も変わらない画面では、通信は点滅するカーソル (0.5 秒ごとに 2 セル) だけです。
**スクロールでも CPU は待たされません**: ターミナルは、ペインタと関係なくビデオ RAM を更新し続け、画面は最新の状態に追いつく形で更新されます (連続出力では、途中の状態は飛ばされる)。

**起動の列**: RESET を 1ms 下げる → 126ms 待つ → `01h` (5.8ms) → `11h` (126ms) → `3Ah` = `55h` → `36h` = MADCTL → `29h` (5.8ms)。MADCTL は、パラメータ (`MADCTL`、既定 `0x28` = MV | BGR)。
`0x28` は、よく使う横向きの設定で、モジュールの実装の向きで鏡像になることがあります (実機で合わせる)。電源とガンマのレジスタ (モジュールごとに違う) は、まだ入れていません。

**SPI のクロック**: 画素クロック (33.75MHz、システムクロックの 1/2) で動かし、`SCK_HALF` クロックで 1 つの半周期にします。

| `SCK_HALF` | SCK | H / L の幅 | 周期 | データシート |
|---|---|---|---|---|
| 1 (既定) | **16.875MHz** | 29.6ns | 59.3ns | 規格外 (H / L 40ns 以上、周期 100ns 以上)。データの設定と保持も 29.6ns で、規格の 30ns にわずかに足りない |
| 2 | 8.4375MHz | 59.3ns | 118.5ns | 規格内 |

ユーザーの指定 (20MHz 前後) に近い値として、既定は 16.875MHz にしました。22.5MHz (÷3) は、67.5MHz からは H / L が非対称になるので、作っていません。
実機で安定しなければ、`SCK_HALF = 2` に落とします (描画は 2 倍遅くなる)。

## 4. 速度 (シミュレーションで確認)

| | `SCK_HALF = 1` | `SCK_HALF = 2` |
|---|---|---|
| 1 セル | 約 126µs | 約 250µs |
| 全画面 (600 セル) | **約 76ms (13 フレーム/秒)** | 約 152ms (6.6 フレーム/秒) |

最初の見積り (126µs / 76ms) とシミュレーションの結果は一致しました。

## 5. 資源とタイミング (Gowin でビルドした結果)

`spilcd/scripts/build_spilcd.sh` で作りました (FUZIX の起動 ROM、`sbc09_soc.v` は git の HEAD、約 70 秒)。

| | HDMI (比較用) | LCD (RGB) | **SPI LCD** |
|---|---|---|---|
| Logic (LUT + ALU) | 7700 (90%) | 7709 (90%) | **7777 / 8640 (91%)** |
| CLS | 95% | 95% | 95% |
| BSRAM | 16 / 26 | 23 / 26 | **13 / 26 (50%)** |
| 画素クロックの Fmax (制約) | 40.4MHz (25.2) | 42.7MHz (33.75) | **39.6MHz (33.75)** |
| clk81 (67.5MHz) の Fmax | 67.9MHz | 68.9MHz | **71.5MHz** (最悪のスラック +0.82ns) |
| 負のスラック (TNS) | 0 | 0 | 0 |

* **タイミング**: 全クロックで制約を満たしています。画素側は Fmax が 39.6MHz で、周期で約 15% の余裕があります。
* **LUT**: 画面なしのビルド (約 5760、別のビルドの参考値) から約 2000 増えます。大半は、デコーダとターミナル (HDMI / RGB 版と共通) で、ペインタと SPI は数百です。
  BSRAM は、ビデオ RAM 2 面、シャドウ RAM、フォントなどで 13 ブロックです (画面なしで 3 ブロック)。
* **同時利用は無理**: SPI LCD のピンは、HDMI や RGB のピンと別ですが、**LUT が足りません**。HDMI を付けたままで SPI 画面を足すと、さらに約 2000 LUT で 8640 を超えます。
  HDMI または SPI LCD のどちらか一方を選びます (最初の検討で「同時に使える」と書いたのは、ピンだけを見た誤りでした)。
* **タイミングの波**: 同じ設計でも、`soc/` の経路 (`io_hit` → `map_u` など) のスラックは、小さな変更で ±0.3ns 動きます (途中のビルドで、画面と関係ない `tcnt` を 32 ビットにしていた版では、clk81 が −0.30ns で失敗した)。
  CLS が 95% を超えると、システムのクロック (67.5MHz) の余裕が少なくなるので、機能を足すときは、毎回ビルドして確かめてください。

## 6. シミュレーションの結果

`make -C fpga/tn9k/spilcd/sim test` (と `make test HALF=2`) で、3 つの入力 (`spi_test.txt` 文字と色と端の文字、`spi_kanji.txt` 15 行 × 20 字の漢字、`spi_scroll.txt` スクロールと行の挿入・削除・消去) を流し、次を確かめました。

* **起動の列**: コントローラが受け取ったコマンドの順番が `01h 11h 3Ah 36h 29h 2Ah 2Bh` で、パラメータが `3Ah` = `55h`、`36h` = `28h` であること。
* **データシートの規則** (`ili9341_model.v` が数える。すべて 0 件):
  * CS から最初の SCL までと、D/CX の設定時間 (`bad_setup`)。
  * 5ms 以内の次のコマンド (`bad_early`)。
  * 16 ビット以外の画素形式 (`bad_format`)。
  * 表示がオンになる前の画素データと、横向き以外のモード (`bad_state`)。
  * SCL の周期が 100ns より短いこと (`fast`) は、`SCK_HALF = 1` で多数。意図した値で、`SCK_HALF = 2` では 0 件。
* **画面の中身** (フレームメモリを画像にして目で確認): 40 桁の定規、色 (ANSI 16 色、反転)、端の文字、漢字・ひらがな・半角カナ、15 行 × 20 字の漢字、スクロール、行の挿入と削除。3 つとも期待どおりでした。
* 全 600 セルが描かれ (76,800 画素、1805 コマンド)、描き終わったあと、通信は止まります。

モデルの簡略化: 横向き (MV = 1) だけを扱い、MX / MY は軸の反転だけです。縦向き、ハードウェアスクロール、`0x28` 以外の向きは、モデルにありません。

## 7. 実機につなぐとき

* **ピンは仮です**。`spilcd.cst` は、回路図のテキストから、現在のビルドで使っていない 3.3V バンクの IO (IOB8A/B、IOB11A/B、IOB13A = 25〜29 番) を選びました。
  これらが基板のヘッダのどの位置か (回路図の PDF のテキストからは分からなかった。Sipeed の Pinmap の図で確認) を見て、番号を直してください。
  31・32・50・63 番 (`RGBINIT`) と、79〜85 番 (1.8V のバンク) は避けます。
* **配線**: FPGA の CS、SCK、MOSI、DC、RESET を、モジュールの 3、7、6、5、4 番へ。VCC は 3.3V または 5V、GND、**LED (8 番) は 3.3V に常時接続** (最初は)。MISO (9 番) とタッチ (10〜14 番) は使いません。
  モジュールのロジックは 3.3V なので、FPGA の 3.3V と直結できます。
* **基板の 1.14 インチ用 SPI コネクタ** (47〜49、76、77、86 番) は使いません。
* 向きと色: 画面が鏡像なら `MADCTL` を変える (`0x68`、`0xE8` など)。色が赤と青で逆なら、BGR のビットを切り替える。
* 映らない、乱れる: まず `SCK_HALF = 2` (8.4MHz、規格内) にする。それでも駄目なら、リセットの時間、起動の待ち、モジュールの初期化の列 (電源とガンマ) を疑う。

## 8. ゲストへ画面の大きさを知らせる方法

画面は 40 桁 × 15 行です。LCD 版 ([LCD.md](LCD.md) 6 章) と同じ方法です。
* **すぐ使える方法**: MK09 は `/ETC/RC.SH` に `stty cols=40 rows=15`、OS-9 は `jwp` の引数で指定します。FUZIX の端末サイズの扱いは、未調査です。
* **レジスタ (提案、未実装)**: `$E00C` (桁数) と `$E00D` (行数) を読み出し専用で足す案。出力 `scr_cols` / `scr_rows` (`spilcd_text.v`) にあります。`sbc09_soc.v` を変えることになるので、見送っています。
* 40 桁は、`jwp` (既定 80 桁、編集の幅 72) には狭いので、`jwp` の桁数の引数を、40 に合わせて使います。

## 9. 検討の経緯と決定

1. **依頼**: 「SPI RGB LCD を接続した場合について、LCD 版と同様な検討を。型式は ILI9341」。
2. **検討**: ILI9341 はフレームメモリを持つので、FPGA は映像を作り続けずに、変わった所を送る方式になる、と整理した。データシートの数値 (10MHz、5ms / 120ms の待ち、`3Ah`、スクロール) を、PDF をローカルでテキストに抽出して確認した。
   基板の回路図も抽出し、空き IO と、基板に 1.14 インチ SPI 液晶のコネクタがあることを確認した。
3. **ユーザーの決定**: 向きは**横向き**、SPI のクロックは **20MHz 前後**、フォントは**既存のもの**、モジュールは **MSP2807** (秋月電子)。
4. **MSP2807 の仕様**: 秋月の資料のテキストから、14 ピン、3.3V ロジック、LED ピンの扱いを確認した。
5. **ユーザーの指示**: 実装に進む。検討を LCD 版と同じく docs に残す。
6. **実装とシミュレーション**: ペインタは、シャドウ RAM との比較で、変わったセルだけを送る方式にした (ダーティビットのビットマップより資源が少ない)。
   最初のシミュレーションで、SPI の「ready」が、投入中のバイトを数えておらず、バイトが落ちる誤りを見つけて直した (コマンドが 1805 件、画素が 76,800 に揃った)。
   `SCK_HALF = 2` (規格内) も、1 つのパラメータで切り替えられるようにした。
7. **ビルド**: 資源とタイミングを測った。途中で、画面と関係ない遅延のカウンタを 32 ビットにしていたため、システム側のタイミングが −0.3ns で失敗した。幅を 23 ビットに減らして、満たした (5 章)。
   同時に、「HDMI と同時に使える」という最初の説明が、LUT の面では誤りと分かった。

**決定のまとめ**

| 項目 | 決定 | 理由 |
|---|---|---|
| 向き | 横向き (40 × 15) | ユーザーの決定。ハードウェアスクロールは使えないが、変更セルだけの再描画で足りる |
| SPI クロック | 16.875MHz (`SCK_HALF = 1`)。落とすなら 8.4375MHz | 「20MHz 前後」に近く、規格 (10MHz) には届かない。画素クロックの 1/2 で、1 つのクロックで済む |
| 描画の方式 | シャドウ RAM との比較 | ダーティビットのビットマップ (600 本) より資源が少ない。書き込みの衝突がない |
| 既存の RTL | 変えない | 検討の段階のため |
| 同時利用 | しない (HDMI と SPI LCD のどちらか) | LUT が足りない |

## 10. 残件 (SPI LCD)

上から順に、実機に進むための必要度が高いものです。

| # | 残件 | 内容 |
|---|---|---|
| 1 | ピンの確認 | 7 章。ヘッダの位置を確かめて、`spilcd.cst` を直す |
| 2 | 実機での確認 | 起動 (リセット、`01h` ... `29h`) が通るか、向き (`MADCTL`) と色順 (BGR)、SCK が 16.875MHz で安定するか (駄目なら `SCK_HALF = 2`) |
| 3 | モジュールの初期化の列 | 電源とガンマのレジスタ。画面が薄い・暗いときに、モジュールの添付コードの列を足す |
| 4 | `build.sh` への分岐 | `SPILCD=1` を足して、トップを `tn9k_spilcd_top`、ファイルを `spilcd/rtl/*.v` と `lcd/rtl/lcd_term.v` に切り替える (既存のスクリプトを変えるので、採用すると決めてから) |
| 5 | ゲストへ画面サイズを知らせる | `$E00C` / `$E00D` のレジスタ (LCD.md と同じ案)。それまでは `stty cols=40 rows=15` |
| 6 | FUZIX の端末の大きさ | 40 × 15 での折り返し |
| 7 | 30 桁 × 20 行 (縦向き) | 縦向きなら、ハードウェアスクロール (`33h` / `37h`) で、改行が 30 セルの再描画で済む。必要になったら、MADCTL とペインタの座標を変える |
| 8 | タッチ (XPT2046) | 使っていない。使うなら、別の SPI のマスタが要る |
| 9 | 置き場の判断 | `fpga/tn9k/spilcd/` のまま持つか、HDMI / LCD と統合して 1 つのビルドの選択肢 (`HDMI=1` / `LCD=1` / `SPILCD=1`) にするか |
