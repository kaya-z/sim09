# LCD 文字画面 (40 ピン RGB パネル): 検討とシミュレーション

Tang Nano 9K の 40 ピン RGB-LCD コネクタに、HDMI 文字画面と同じ文字画面を出すための検討です (2026-11-05)。
パネルは **SH500J01Z 相当** (5 インチ、800×480、RGB565) を想定しています。**HDMI とは排他** (ピン 68〜75 が共通) です。

**状態: RTL は書いてシミュレーション (Verilator) で確かめました。ビットストリームは作っていません。実機でも試していません。**
既存の RTL (`fpga/tn9k/rtl/`) と制約ファイルは、1 つも変えていません。追加したものは `fpga/tn9k/lcd/` にあります。

## 1. 構成

| ファイル | 内容 |
|---|---|
| `fpga/tn9k/lcd/rtl/lcd_text.v` | 文字画面の本体 (`hdmi_text.v` の LCD 版)。デコーダ (`hdmi_decode.v`) と PSRAM の橋渡し (`psram_xfer.v`) は HDMI 用をそのまま使う |
| `fpga/tn9k/lcd/rtl/lcd_term.v` | ターミナル (`hdmi_term.v` の 100×30 版。セルのアドレスを 12 ビットにし、行の先頭の計算を桁数のパラメータにした) |
| `fpga/tn9k/lcd/rtl/lcd_video.v` | 表示側。800×480 のタイミング、RGB565 の出力、DE / HSYNC / VSYNC |
| `fpga/tn9k/lcd/rtl/lcd_glyph.v` | 漢字のグリフエンジン (`hdmi_glyph.v` の 100 桁版) |
| `fpga/tn9k/lcd/rtl/lcd_pll.v` | `tn9k_pll.v` と同じ PLL に、分周出力 (CLKOUTD = 33.75MHz) を足したもの |
| `fpga/tn9k/lcd/rtl/tn9k_lcd_top.v` | トップ (`tn9k_top.v` の HDMI の所を LCD に替えたもの。**合成していない**。Verilator の lint だけ通した) |
| `fpga/tn9k/lcd/constraints/lcd.cst`, `lcd.sdc` | LCD のピンとクロックの制約 (`tn9k.cst` と一緒に使う。`hdmi.cst` の代わり) |
| `fpga/tn9k/lcd/sim/` | Verilator のテスト (`make test`) |

## 2. パネルとタイミング

ピンは Sipeed の制約ファイル (Tang Nano 9K の LCD の例) のとおりです。電圧は LVCMOS33 です。

| 信号 | ピン |
|---|---|
| `LCD_CLK` | 35 |
| `LCD_HYNC` (水平同期)、`LCD_SYNC` (垂直同期)、`LCD_DEN` | 40、34、33 |
| 赤 R[4:0] | 75 74 73 72 71 |
| 緑 G[5:0] | 70 69 68 57 56 55 |
| 青 B[4:0] | 54 53 51 42 41 |

| 項目 | 値 |
|---|---|
| ピクセルクロック | **33.75MHz** (システムクロック 67.5MHz の 1/2。同じ PLL の CLKOUTD。Sipeed の例は 33.0MHz。パネルは約 33MHz) |
| 1 行 | 1192 クロック (= 149 セル)。表示 800 + 前縁 210 + 同期 1 + 後縁 181 |
| 1 画面 | 548 行。表示 480 + 前縁 57 + 同期 5 + 後縁 6 |
| 更新 | 33.75MHz / (1192 × 548) = **51.7Hz** |
| 同期 | DE モード。HSYNC / VSYNC は負極性のパルス (DE モードのパネルは見ません) |
| 色 | RGB565 (赤は 24 ビットの上位 5 ビット、緑は 6、青は 5) |

**パネルのデータシートは、まだ読めていません** (Sipeed のサイトからの取得が途中で切れました)。上のタイミングは、Sipeed の LCD の例によります。
実機に進む前に、データシートで次を確かめてください: ピクセルクロックの範囲、DE モードの条件、電源電圧 (3.3V か 2.8V か。駆動 IC の記載が資料で食い違う)、
クロックの採取エッジ (今は `LCD_CLK = clk_pix` で、データはクロックの立ち上がりのあとに変わる。Sipeed の例と同じ)。

## 3. 画面: 100 桁 × 30 行

800÷8 = 100 桁、480÷16 = 30 行で、パネルがちょうど埋まります (HDMI 版のような上下の黒枠はない)。全角の漢字は 1 行に 50 字です。
ターミナルの機能 (ESC シーケンス、色、スクロール領域、全角文字の折り返し、漢字のデコード) は、HDMI 版と同じです。

| | HDMI | LCD |
|---|---|---|
| 画面 | 80×25 (2000 セル) | 100×30 (3000 セル) |
| ピクセルクロック | 25.2MHz (+ 126MHz) | 33.75MHz だけ |
| 映像の出力 | TMDS の符号化と 10:1 シリアライザ | RGB565 をそのまま出す (符号化もシリアライザも要らない) |
| ビデオ RAM | 3 面 × 2048 語 × 24 ビット | 3 面 × 3000 語 × 24 ビット |

**資源の見積り (合成はしていない)**: ビデオ RAM が 1 面あたり 3 ブロックから 4 ブロックになる見込みで、BSRAM は 16 / 26 から約 19 / 26 に増える見込みです。
TMDS 側の LUT が要らなくなるので、LUT は今の 86% より減る見込みです。実際の値は、ビットストリームを作ってみないと分かりません。

## 4. シミュレーションの結果

`make -C fpga/tn9k/lcd/sim test` (Verilator。HDMI 用のデコーダ、PSRAM のモデル、漢字のイメージは、既存のものをそのまま使う) で次を確かめました。

* **タイミング**: 1 行 1192 クロック、1 画面 548 行、DE が 800×480、HSYNC が 1 クロック、VSYNC が 5 行。ずれは 0 件でした。
* **画面の中身** (PPM の画像で目で確認): 100 桁の定規、30 行目と 100 桁目の端の文字、色 (ANSI の 16 色、反転)、漢字・ひらがな・半角カナ、
  スクロール、行の挿入と削除 (`ESC [ L` / `M`)、行の消去、右端での全角文字の折り返し。
* **最悪の場合の漢字の取得**: 30 行 × 50 字をすべて漢字にした画面 (`lcd_kanji.txt`) が、欠けなく出ました。
  1 行のセルは 80 から 100 に 25% 増え、1 行の時間は 14% しか増えませんが、PSRAM の取得は間に合いました。
  ただし PSRAM のモデルの遅延はボードのものと同じではないので、実機で漢字の画面を確かめる必要があります (CPU や SD と PSRAM を取り合う)。

## 5. ゲストへ画面の大きさを知らせる方法

ゲスト (FUZIX、MK09、OS-9) は、画面が 80 桁だと思って動きます (`jwp` の既定は 80×24)。LCD 版では次のようにします。

1. **今すぐ使える方法 (ハードの変更なし)**: ゲストの側で桁数と行数を指定します。
   * MK09: `stty cols=100 rows=30` を `/ETC/RC.SH` に書きます (`jwp` と `more` が使います)。
   * OS-9: `jwp` の起動引数で指定します。
   * FUZIX: 端末の大きさの扱いは、まだ調べていません (FUZIX の端末ドライバと `stty` に、桁数と行数の設定があるかを確かめる必要があります)。
2. **レジスタ (提案。まだ実装していない)**: I/O ページの空きの 2 つのレジスタを、読み出し専用にします。

   | アドレス (Level 1 / Level 2) | 内容 |
   |---|---|
   | `$E00C` / `$FF8C` | 桁数 (LCD 版は 100。HDMI 版と、レジスタのない版は 0 = 80×25 とみなす) |
   | `$E00D` / `$FF8D` | 行数 (LCD 版は 30) |

   値は `lcd_text` の出力 `scr_cols` / `scr_rows` (定数) にあります。`sbc09_soc.v` に 2 つの読み出しを足すだけで済みますが、
   既存の RTL を変えることになるので、今回は見送りました。足す場合は、`sim09` にも同じレジスタ (80 と 24) を足し、
   ゲストの `jwp` / `stty` / FUZIX の端末が、起動時に読んで大きさを決めるようにします。
3. 端末が `ESC [ 6 n` (カーソル位置) や `ESC [ 18 t` (画面の大きさ) に答える方法は、採りません。ACIA の受信側へ文字を入れる経路が要り、
   `acia_uart.v` と `sbc09_soc.v` の変更が大きくなるためです。
