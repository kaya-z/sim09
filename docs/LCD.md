# LCD 文字画面 (40 ピン RGB パネル): 検討とシミュレーション

Tang Nano 9K の 40 ピン RGB-LCD コネクタに、HDMI 文字画面と同じ文字画面を出すための検討です (2026-11-05)。
パネルは **SH500J01Z 相当** (5 インチ、800×480、RGB565) を想定しています。**HDMI とは排他** (ピン 68〜75 が共通) です。

**状態: RTL は書いて、シミュレーション (Verilator) と Gowin のビルド (資源とタイミング) で確かめました。実機には書いていません。**
既存の RTL (`fpga/tn9k/rtl/`) と制約ファイルは、1 つも変えていません。追加したものは `fpga/tn9k/lcd/` にあります。

## 1. 構成

| ファイル | 内容 |
|---|---|
| `fpga/tn9k/lcd/rtl/lcd_text.v` | 文字画面の本体 (`hdmi_text.v` の LCD 版)。デコーダ (`hdmi_decode.v`) と PSRAM の橋渡し (`psram_xfer.v`) は HDMI 用をそのまま使う |
| `fpga/tn9k/lcd/rtl/lcd_term.v` | ターミナル (`hdmi_term.v` の 100×30 版。セルのアドレスを 12 ビットにし、行の先頭の計算を桁数のパラメータにした) |
| `fpga/tn9k/lcd/rtl/lcd_video.v` | 表示側。800×480 のタイミング、RGB565 の出力、DE / HSYNC / VSYNC |
| `fpga/tn9k/lcd/rtl/lcd_glyph.v` | 漢字のグリフエンジン (`hdmi_glyph.v` の 100 桁版) |
| `fpga/tn9k/lcd/rtl/lcd_pll.v` | `tn9k_pll.v` と同じ PLL に、分周出力 (CLKOUTD = 33.75MHz) を足したもの |
| `fpga/tn9k/lcd/rtl/tn9k_lcd_top.v` | トップ (`tn9k_top.v` の HDMI の所を LCD に替えたもの。**合成していない**。Verilator の lint だけ通した) |
| `fpga/tn9k/lcd/constraints/lcd.cst`, `lcd.sdc` | LCD のピンとクロックの制約 (`tn9k.cst` と一緒に使う。`hdmi.cst` の代わり) |
| `fpga/tn9k/lcd/sim/` | Verilator のテスト (`make test`) |
| `fpga/tn9k/lcd/scripts/` | Gowin のビルド (`build_lcd.sh`) と、比較用の HDMI 版のビルド (`build_hdmi_base.sh`) |

## 2. パネルとタイミング

ピンは Sipeed の制約ファイル (Tang Nano 9K の LCD の例) のとおりです。電圧は LVCMOS33 です。

| 信号 | ピン |
|---|---|
| `LCD_CLK` | 35 |
| `LCD_HYNC` (水平同期)、`LCD_SYNC` (垂直同期)、`LCD_DEN` | 40、34、33 |
| 赤 R[4:0] | 75 74 73 72 71 |
| 緑 G[5:0] | 70 69 68 57 56 55 |
| 青 B[4:0] | 54 53 51 42 41 |

| 項目 | 値 |
|---|---|
| ピクセルクロック | **33.75MHz** (システムクロック 67.5MHz の 1/2。同じ PLL の CLKOUTD。Sipeed の例は 33.0MHz。パネルは約 33MHz) |
| 1 行 | 1192 クロック (= 149 セル)。表示 800 + 前縁 210 + 同期 1 + 後縁 181 |
| 1 画面 | 548 行。表示 480 + 前縁 57 + 同期 5 + 後縁 6 |
| 更新 | 33.75MHz / (1192 × 548) = **51.7Hz** |
| 同期 | DE モード。HSYNC / VSYNC は負極性のパルス (DE モードのパネルは見ません) |
| 色 | RGB565 (赤は 24 ビットの上位 5 ビット、緑は 6、青は 5) |

**パネルは Sipeed の 5 インチ RGB パネルのサンプルと同じもの** (ユーザーの確認、2026-11-05) なので、Sipeed の LCD のサンプル (ピン、33MHz、DE モード、負極性の同期、RGB565) を、
このパネルの仕様として扱います。データシートの PDF は取得できませんでしたが、これが根拠なので、電源電圧 (資料によって 3.3V と 2.8V の記載がある) は、サンプルが動く基板の側で決まります。
サンプルと違う所は次の 2 つで、どちらもパネルの許す範囲と見ています (実機で確かめる):
* ピクセルクロックは 33.75MHz (サンプルは 33.0MHz。サンプルのページは「33.3MHz が要る」と書いている)。更新は 51.7Hz になる (サンプルは 33.0MHz で約 50.5Hz)。
* HSYNC / VSYNC の幅と porch の値は、サンプルの数字をそのまま使わず、DE モードで 1 行 1192 クロック、1 画面 548 行になるように置いた (総数はサンプルと同じ)。

## 3. 画面: 100 桁 × 30 行

800÷8 = 100 桁、480÷16 = 30 行で、パネルがちょうど埋まります (HDMI 版のような上下の黒枠はない)。全角の漢字は 1 行に 50 字です。
ターミナルの機能 (ESC シーケンス、色、スクロール領域、全角文字の折り返し、漢字のデコード) は、HDMI 版と同じです。

| | HDMI | LCD |
|---|---|---|
| 画面 | 80×25 (2000 セル) | 100×30 (3000 セル) |
| ピクセルクロック | 25.2MHz (+ 126MHz) | 33.75MHz だけ |
| 映像の出力 | TMDS の符号化と 10:1 シリアライザ | RGB565 をそのまま出す (符号化もシリアライザも要らない) |
| ビデオ RAM | 3 面 × 2048 語 × 24 ビット | 3 面 × 3000 語 × 24 ビット (BSRAM は 4 章) |

## 4. 資源とタイミング (Gowin でビルドした結果)

LCD 版を `fpga/tn9k/lcd/scripts/build_lcd.sh` で、比較用の HDMI 版を `build_hdmi_base.sh` で、同じ条件 (FUZIX の起動 ROM、`sbc09_soc.v` は git の HEAD、ビルド約 80 秒) で作りました。
ビットストリーム (`lcd/build/fuzix/impl/pnr/sbc09_lcd.fs`) はできていますが、実機には書いていません。

| | HDMI (比較用) | LCD |
|---|---|---|
| Logic (LUT + ALU) | 7700 / 8640 (90%) | 7709 / 8640 (90%) |
| CLS | 4069 / 4320 (95%) | 4076 / 4320 (95%) |
| レジスタ | 2347 (35%) | 2305 (35%) |
| **BSRAM** | 16 / 26 (62%) | **23 / 26 (89%)** |
| DSP (MULT9X9) | 0 | 0.75 / 10 (3 個) |
| IO ポート | 26 / 71 | 38 / 71 |
| clk81 (67.5MHz) の Fmax | 67.86MHz | 68.95MHz |
| 画素クロックの Fmax | 40.4MHz (制約 25.2MHz) | **42.7MHz (制約 33.75MHz)** |
| 負のスラック (TNS) | 0 | 0 (setup / hold とも) |

* **タイミング**: 全部のクロックで制約を満たしています。画素側 (33.75MHz) は、Fmax が 42.7MHz なので、周期で約 6ns (26%) の余裕があります。
  システム側 (67.5MHz) の最悪のスラックは +0.31ns (HDMI 版は +0.08ns) で、これは既存の `soc/loader` の経路です。LCD 版が良いのは配置の違いで、LCD の変更のせいではありません。
* **BSRAM**: ビデオ RAM が 3 面とも 3000 語になったので、**見積り (19 / 26) より多い 23 / 26** になりました。空きは 3 ブロックです。
  ここが一番きつい資源で、これ以上の機能 (属性の追加など) を足すと、BSRAM が先に足りなくなります。
  減らすなら、`{属性 8, 種別 4, 符号 12}` の 24 ビットの語の、種別 (0 / 1 / 2 だけ) を 2 ビットにして 22 ビットにするのが簡単です (BSRAM の幅の区切りによっては効かないので、やるなら試す)。
* **LUT / CLS**: HDMI 版とほぼ同じです (TMDS の符号化が要らなくなる分より、ターミナルとビデオの 100×30 化の増加の方が大きい。当初の「減る」という見積りは外れました)。両方とも CLS が 95% で、余裕は少ないです。
* **DSP**: `lcd_term.v` の行の先頭の計算 (`r * COLS`) が 9×9 の乗算器 3 個になりました。使い切る心配はありませんが、LUT で済ませたければ、`lcd_video.v` のようにシフトと加算で書き直せます。
* ピンの割り当ては、`lcd.cst` のとおりに配置されました (LCD_CLK は専用のクロックピン 35、LVCMOS33)。

## 5. シミュレーションの結果

`make -C fpga/tn9k/lcd/sim test` (Verilator。HDMI 用のデコーダ、PSRAM のモデル、漢字のイメージは、既存のものをそのまま使う) で次を確かめました。

* **タイミング**: 1 行 1192 クロック、1 画面 548 行、DE が 800×480、HSYNC が 1 クロック、VSYNC が 5 行。ずれは 0 件でした。
* **画面の中身** (PPM の画像で目で確認): 100 桁の定規、30 行目と 100 桁目の端の文字、色 (ANSI の 16 色、反転)、漢字・ひらがな・半角カナ、
  スクロール、行の挿入と削除 (`ESC [ L` / `M`)、行の消去、右端での全角文字の折り返し。
* **最悪の場合の漢字の取得**: 30 行 × 50 字をすべて漢字にした画面 (`lcd_kanji.txt`) が、欠けなく出ました。
  1 行のセルは 80 から 100 に 25% 増え、1 行の時間は 14% しか増えませんが、PSRAM の取得は間に合いました。
  ただし PSRAM のモデルの遅延はボードのものと同じではないので、実機で漢字の画面を確かめる必要があります (CPU や SD と PSRAM を取り合う)。

## 6. ゲストへ画面の大きさを知らせる方法

ゲスト (FUZIX、MK09、OS-9) は、画面が 80 桁だと思って動きます (`jwp` の既定は 80×24)。LCD 版では次のようにします。

1. **今すぐ使える方法 (ハードの変更なし)**: ゲストの側で桁数と行数を指定します。
   * MK09: `stty cols=100 rows=30` を `/ETC/RC.SH` に書きます (`jwp` と `more` が使います)。
   * OS-9: `jwp` の起動引数で指定します。
   * FUZIX: 端末の大きさの扱いは、まだ調べていません (FUZIX の端末ドライバと `stty` に、桁数と行数の設定があるかを確かめる必要があります)。
2. **レジスタ (提案。まだ実装していない)**: I/O ページの空きの 2 つのレジスタを、読み出し専用にします。

   | アドレス (Level 1 / Level 2) | 内容 |
   |---|---|
   | `$E00C` / `$FF8C` | 桁数 (LCD 版は 100。HDMI 版と、レジスタのない版は 0 = 80×25 とみなす) |
   | `$E00D` / `$FF8D` | 行数 (LCD 版は 30) |

   値は `lcd_text` の出力 `scr_cols` / `scr_rows` (定数) にあります。`sbc09_soc.v` に 2 つの読み出しを足すだけで済みますが、
   既存の RTL を変えることになるので、今回は見送りました。足す場合は、`sim09` にも同じレジスタ (80 と 24) を足し、
   ゲストの `jwp` / `stty` / FUZIX の端末が、起動時に読んで大きさを決めるようにします。
3. 端末が `ESC [ 6 n` (カーソル位置) や `ESC [ 18 t` (画面の大きさ) に答える方法は、採りません。ACIA の受信側へ文字を入れる経路が要り、
   `acia_uart.v` と `sbc09_soc.v` の変更が大きくなるためです。

## 7. 実機に進むとき

1. パネルのデータシートで、2 章の確認項目 (データシート)を確かめる。
2. `build.sh` に LCD 版の分岐を足す (`tn9k_lcd_top`、`lcd/rtl/*.v`、`lcd/constraints/*`。HDMI のファイルは外す)。
3. (済) ビットストリームは作ってあり、タイミングは満たしている (4 章)。
4. 実機で、起動メッセージ、`login:`、漢字を確かめる。

## 8. 検討の経緯と決定

LCD 対応は、次の順の議論で決まりました (2026-11-05)。

1. **できるか**: Tang Nano 9K の基板には 40 ピンの RGB-LCD コネクタがあり、できると答えた。HDMI とは排他でよい (ピン 68〜75 が共通) と、ユーザーが決めた。
   このとき、リポジトリには LCD のピン定義がなく、`tn9k.cst` と `hdmi.cst` だけだった。
2. **パネル**: SH500J01Z 相当 (5 インチ、800×480、RGB565) と、ユーザーが指定した。画面は、HDMI の 80×25 のままにせず、**LCD に合わせた桁数 (100×30)** にすると、ユーザーが決めた。
3. **検討**: ピンとタイミングを Sipeed の資料から取り (データシートの PDF は取得に失敗)、変更の範囲 (ターミナルのアドレス幅、ビデオのタイミング、ピクセルクロック、トップ、制約) を整理した。
   この段階では**実装しない**ことにした。
4. **実装の範囲**: ユーザーの指示は「ゲストへ画面サイズを知らせる範囲は任せる。RTL はシミュレーションまででよい。**既存の RTL は上書きしない**(これは見積りなので)」。
   これに従い、既存のファイルは 1 つも変えず、`fpga/tn9k/lcd/` に新しいファイルを足した (HDMI 用のデコーダなどは、そのまま共用した)。
   ゲストへの通知は、レジスタ (`$E00C` / `$E00D`) を提案するだけにして実装せず、すぐ使える方法 (MK09 の `stty cols= rows=`、`jwp` の引数) を示した (6 章)。
5. **シミュレーション**: Verilator で、タイミング、画面の中身、漢字の最悪の場合 (30 行 × 50 字) を確かめた (5 章)。途中で、テストベンチの数え方のずれと、
   テスト文の文字コード (この環境のロケールが EUC-JP で、UTF-8 を明示しないと日本語が化けた) を直した。
6. **資源とタイミング**: ユーザーの追加の指示で、Gowin でビルドして測った (4 章)。見積りは 2 点外れた: BSRAM は 19 ではなく 23 / 26 で、LUT は減らなかった。
   タイミングは満たした。
7. **パネル** (最後の確認): ユーザーが、パネルは Sipeed のサンプルのものと同じと確認した。データシートが読めなくても、サンプルを根拠にできる。

**決定のまとめ**

| 項目 | 決定 | 理由 |
|---|---|---|
| ピクセルクロック | システム PLL の CLKOUTD (67.5MHz / 2 = 33.75MHz) | 新しい PLL が要らず、2 つのクロックが同期する。パネルは約 33MHz |
| 画面 | 100×30 | 800×480 をちょうど埋める |
| 同期方式 | DE モード、同期は負極性 | Sipeed の例とパネルの仕様 |
| 既存の RTL | 変えない | 見積りの段階のため |
| ゲストへの通知 | 提案のみ (レジスタ 2 つ)。当面は `stty` / `jwp` の引数 | 既存の `sbc09_soc.v` を変えないため |

**残っていること**: クロックの採取エッジ (今はサンプルと同じ構成)、`build.sh` への LCD 版の分岐、実機での確認、
FUZIX の端末の大きさの扱いの調査、BSRAM が 3 ブロックしか空かない問題 (機能を足す前に語の幅を詰める)。

## 9. 残件 (LCD 対応)

2026-11-05 の時点で、やっていないことの一覧です。上から順に、実機に進むための必要度が高いものです。

| # | 残件 | 内容 |
|---|---|---|
| 1 | `build.sh` への LCD 版の分岐 | 今は `lcd/scripts/build_lcd.sh` が別に作っています。`build.sh` に `LCD=1` を足して、トップを `tn9k_lcd_top`、ファイルを `lcd/rtl/*.v`、制約を `lcd/constraints/*` に切り替える (HDMI のファイルは外す)。既存のスクリプトを変えるので、見積りでなく採用すると決めてから |
| 2 | 実機での確認 | 起動メッセージ、`login:`、漢字、色、スクロール。まずクロックの採取エッジ (今は `LCD_CLK = clk_pix`、Sipeed のサンプルと同じ構成) を見る。漢字の画面は、PSRAM を CPU や SD と取り合うので、30 行すべて漢字にしても欠けないか確かめる (シミュレーションは通った) |
| 3 | ピクセルクロックの 33.0MHz 版 | 33.75MHz で映らなかった場合だけ。サンプルは 33.0MHz。PLL を作り直す (27MHz × 11 / 9 は PFD が 3MHz の下限になるので、別の組み合わせか、システムクロックの変更を伴う) |
| 4 | ゲストへ画面サイズを知らせる | 読み出し専用レジスタ `$E00C` / `$E00D` (Level 2 は `$FF8C` / `$FF8D`)。`sbc09_soc.v`、`sim09`、ゲスト (`jwp`、`stty`、FUZIX の端末) の 3 か所を変える。それまでは MK09 の `stty cols=100 rows=30` と、OS-9 の `jwp` の引数で指定する |
| 5 | FUZIX の端末の大きさ | FUZIX の端末ドライバと `stty` に、桁数と行数の設定があるか、100×30 で折り返しが合うかを調べる |
| 6 | BSRAM の空きが 3 ブロックだけ (23 / 26) | 機能を足す前に、ビデオ RAM の語を 24 ビットから 22 ビットに詰める (種別 4 ビットを 2 ビットに)。BSRAM の幅の区切りで効くかどうかは、ビルドして確かめる |
| 7 | 乗算器 (DSP 3 個) | `lcd_term.v` の `r * COLS` をシフトと加算に書き直せば、DSP は 0 になる (なくてもよい) |
| 8 | パネルの電源電圧とバックライト | Sipeed のサンプルが動く基板と同じ構成なら問題ない。バックライトの制御ピンは、サンプルの制約ファイルにないので、基板でいつも点灯する構成と見ている |
| 9 | 最終の置き場の判断 | `fpga/tn9k/lcd/` のまま持つか、HDMI 版と統合して 1 つのビルドの選択肢 (`HDMI=1` か `LCD=1`) にするか |
